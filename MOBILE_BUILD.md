# Как получить приложение на телефоне

Есть два пути. Начните с первого — он самый простой и работает уже сегодня
и на Android, и на iPhone.

## Вариант 1 — PWA (без сборки, работает уже сейчас)

Проект уже настроен как PWA (manifest.json + service worker). Достаточно
задеплоить сервер (например, на Railway — конфиг `railway.json` уже есть
в проекте) и открыть публичный URL в браузере на телефоне:

- **Android (Chrome):** откройте сайт → меню (⋮) → «Установить приложение».
- **iPhone (Safari):** откройте сайт → кнопка «Поделиться» → «На экран
  «Домой»».

Иконка появится на рабочем столе, приложение откроется в полноэкранном
режиме без адресной строки — по ощущениям как обычное приложение. Это
не требует Android Studio, Xcode или публикации в сторах.

## Вариант 2 — настоящий .apk и .ipa через Capacitor

Если нужен именно файл `.apk` для установки вручную (или публикация
в Google Play / App Store), используйте Capacitor — он оборачивает уже
задеплоенный сайт в нативное приложение (WebView + доступ к нативным API).

**Важно:** мессенджер работает через живое соединение (Socket.io) с
сервером, поэтому сначала задеплойте `server.js` куда-нибудь публично
(Railway, Render и т.п.) и получите постоянный URL. Локальный `localhost`
для этого не подходит.

### Шаги для Android (.apk)

Понадобится: Node.js, Android Studio (бесплатно, с Android SDK).

```bash
npm install
npx cap init            # appId и appName уже заданы в capacitor.config.json
npx cap add android
```

Откройте `capacitor.config.json` и замените `server.url` на ваш реальный
адрес после деплоя (например `https://dani-mesend-production.up.railway.app`).

```bash
npx cap sync android
npx cap open android
```

Откроется Android Studio. Дальше: `Build → Build Bundle(s) / APK(s) →
Build APK(s)`. Готовый `.apk` появится в
`android/app/build/outputs/apk/debug/`. Его можно скинуть на телефон
и установить (на Android нужно будет разрешить установку из
неизвестных источников), либо собрать подписанный release-билд для
Google Play через `Build → Generate Signed Bundle / APK`.

### Шаги для iOS (.ipa)

Здесь есть жёсткое ограничение Apple: собрать и подписать iOS-приложение
можно **только на macOS через Xcode**, и для установки на реальный iPhone
(или публикации в App Store) нужен Apple Developer аккаунт
(бесплатный — приложение будет работать 7 дней и требует пересборки;
платный, $99/год — для TestFlight и App Store). Я не могу выполнить
эту часть за вас в этом чате — Xcode доступен только на Mac.

Когда у вас будет доступ к Mac:

```bash
npm install
npx cap add ios
npx cap sync ios
npx cap open ios
```

Откроется Xcode. Укажите свою команду разработчика (Signing & Capabilities),
подключите iPhone или выберите симулятор, нажмите Run — либо
`Product → Archive` для сборки `.ipa` и публикации через TestFlight.

## Регистрация, история чата и уведомления (новое)

### Аккаунты и сохранение истории

Теперь вместо общего кода на всех — полноценная регистрация: имя +
пароль (код белого списка нужен только один раз, при регистрации).
Все пользователи, сообщения и токены сессий хранятся в файлах
`data/users.json`, `data/messages.json`, `data/sessions.json` рядом с
сервером — без внешней базы данных, чтобы не усложнять деплой.

При входе выбор «Запомнить меня» сохраняет токен сессии в
`localStorage` браузера — при следующем открытии приложение входит
само, без повторного ввода пароля.

**⚠️ Важно про Railway (и большинство подобных хостингов):** диск там
эфемерный — при каждом новом деплое содержимое `data/` обнулится, и
все аккаунты/история переписки пропадут. Чтобы это исправить,
подключите постоянный том (Railway → ваш сервис → Settings → Volumes
→ Add Volume, точка монтирования `/app/data`). Без этого шага
регистрация будет "слетать" при каждом обновлении кода.

### Push-уведомления (работают даже при закрытом приложении)

Уведомления о новых сообщениях работают в два уровня:

1. **Пока вкладка/PWA открыты, но не в фокусе** — работает сразу,
   ничего настраивать не нужно (обычный браузерный Notification API).
2. **Когда приложение полностью закрыто** — нужен настоящий Web Push,
   для него требуются VAPID-ключи (это просто пара ключей для
   подписи, бесплатно, не требует внешних сервисов вроде Firebase).

Как включить push-уведомления:

```bash
npm install
npx web-push generate-vapid-keys
```

Команда выведет `Public Key` и `Private Key`. Добавьте их как
переменные окружения на хостинге (Railway → Variables):

```
VAPID_PUBLIC_KEY=...
VAPID_PRIVATE_KEY=...
```

После рестарта сервера в логах пропадёт предупреждение "Push-уведомления
выключены", и при следующем входе в приложение браузер спросит
разрешение на уведомления. Если ключи не заданы — всё остальное
(чат, история, уведомления при открытой вкладке) продолжает работать
как обычно, просто без push при закрытом приложении.

## Что уже сделано в этом обновлении кода

- Ответ на сообщение (нажмите на любое сообщение → появится плашка
  «Ответ для …» над полем ввода → цитата отображается в отправленном
  сообщении).
- Статус прочтения: одна галочка ✓ — отправлено, две синие галочки ✓✓ —
  сообщение прочитано хотя бы одним из получателей.
- Исправлен PWA: `manifest.json` и `sw.js` перенесены в `public/` (иначе
  сервер их не отдавал), убрана опечатка `Const` → `const` в `sw.js`,
  иконки манифеста теперь берутся из локальных файлов, а не с внешнего CDN.
- Удалены задвоенные `<!DOCTYPE html>` и повторная регистрация
  service worker в `index.html`.
- Регистрация/вход по имени и паролю (код белого списка нужен только
  при регистрации), автовход по сохранённому токену, кнопка «Выйти».
- История чата сохраняется на сервере (`data/messages.json`) и
  подгружается заново при входе (последние 100 сообщений).
- Уведомления о новых сообщениях: мгновенные — пока вкладка открыта в
  фоне, и настоящие push — когда приложение полностью закрыто (нужна
  разовая настройка VAPID-ключей, см. выше).
